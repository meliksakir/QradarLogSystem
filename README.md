\# QRadar Log Management System



QRadar Log Management System is a full-stack log processing and security event management project developed to simulate a QRadar-oriented event processing workflow.



The system receives security events from manual input or dataset files, parses and normalizes the records, stores them in SQL Server, generates application logs, and presents the processed data through a React-based monitoring interface.



\## Project Features



\- Security event parsing and normalization

\- SQL Server event persistence

\- Severity classification

\- Application logging

\- Dashboard and system health monitoring

\- Event searching and filtering

\- Manual event processing

\- Multi-event processing

\- Dataset import and automatic format detection

\- Drag-and-drop dataset upload

\- Processing performance measurement

\- REST API architecture



\## Supported Dataset Formats



The Dataset Import module currently supports:



\- LEEF 1.0

\- LEEF 2.0

\- CSV

\- JSON

\- JSONL

\- Key-value text records



Unsupported formats are detected and rejected with an appropriate error response.



\## Architecture



The project consists of three main layers:



\### Backend



Developed with ASP.NET Core Web API and C#.



Main responsibilities:



\- Receiving API requests

\- Parsing raw security events

\- Normalizing event data

\- Dataset format detection

\- Dataset parsing

\- Event processing

\- Database operations

\- File-based application logging

\- System health information



\### Frontend



Developed with React, TypeScript and Vite.



The interface contains:



\- Dashboard

\- Events

\- Logs

\- User Input

\- Dataset Import



The frontend communicates with the ASP.NET Core backend through REST API endpoints.



\### Database



Microsoft SQL Server is used for persistent event storage.



Processed events contain information such as:



\- QID

\- Event name

\- Source IP

\- Destination IP

\- Source port

\- Destination port

\- Username

\- Severity

\- Severity level

\- Magnitude

\- Log source

\- Parse status

\- Processing time

\## Main Backend Components



\### EventParser



Converts raw key-value event data into structured event objects.



\### EventNormalizer



Normalizes parsed event information and determines the severity level.



\### EventProcessingService



Coordinates parsing, normalization, database persistence and logging operations.



\### DatasetFormatDetector



Automatically determines the format of uploaded dataset files.



\### DatasetImportService



Processes dataset files and routes records to the appropriate parser.



\### Format Parsers



Format-specific parsers are implemented for:



\- LEEF

\- CSV

\- JSON / JSONL



\### LogReaderService



Reads application logs and makes them available to the frontend through the API.



\## API Endpoints



The backend provides endpoints for operations including:



```text

POST /api/Dataset/upload

GET  /api/Events

POST /api/Events

GET  /api/Events/{id}

POST /api/Events/parse

POST /api/Events/parse-multiple

GET  /api/Logs
```

Swagger/OpenAPI is available in the development environment for API testing.



\## Frontend Modules

\## Running the Project



\### Requirements



Install:



\- .NET SDK

\- Node.js and npm

\- Microsoft SQL Server

\- SQL Server Management Studio



\### Database Configuration



Update the SQL Server connection string in:



```text

QradarLogSystem.Api/appsettings.json

```



Example:



```text

Server=YOUR\_SQL\_SERVER;Database=QradarLogDB;Trusted\_Connection=True;TrustServerCertificate=True;

```



The SQL Server instance name must be changed according to the computer on which the project is running.



\### Run Backend



Open:



```text

QradarLogSystem.sln

```



with Visual Studio and start `QradarLogSystem.Api`.



\### Run Frontend



Open a terminal in:



```text

qradar-log-frontend

```



Then run:



```bash

npm install

npm run dev

```



The React application will start through Vite.



\## Project Purpose



This project was developed as an internship project to study security log processing, QRadar-oriented event formats, REST API architecture, SQL-based event persistence, application logging, dataset processing and frontend security monitoring.



The project demonstrates an end-to-end pipeline from raw security event ingestion to processing, storage, logging and visualization.
